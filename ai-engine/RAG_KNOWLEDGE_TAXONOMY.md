### 1-5. RAG 시스템 지식 분류 모범 사례

**청킹 전략:**
- 재귀적 분할(Recursive Splitting)이 80% RAG 앱의 기본 선택
- 시맨틱 청킹은 정확도 최대 70% 향상 (기본 대비)
- 최적 청크 크기: 512 토큰 (재귀적 분할 시 69% 정확도)
- 더 짧고 정확한 컨텍스트가 긴 것보다 나은 성능

**계층적 RAG 구조:**
- 도메인별 Taxonomy 정의가 핵심
- 예: 의료 → 전공분야 → 질환 → 치료법 → 연구논문
- 메타데이터(출처, 날짜, 문서유형) 필터링이 정확도에 중요
- GraphRAG: 온톨로지+택소노미로 관계까지 정의

## 3. BAAL 페르소나용 RAG 지식 체계 제안

### 설계 원칙
1. **2계층 구조**: 공통 상식 (모든 페르소나) + 전문 지식 (페르소나별)
2. **한국 중심**: 한국 사회/문화 맥락이 최우선
3. **시의성 분리**: 변하지 않는 지식(정적) vs 자주 업데이트되는 지식(동적)
4. **청크 단위**: 1 청크 = 1 토픽, 300~500토큰 (한국어 기준 약 150~250자)

## 5. 구현 권장사항

### 5-1. 청크 설계
```
{
  "chunk_id": "A2_003",
  "category": "한국사회상식.경제생활",
  "subcategory": "고용",
  "title": "2026년 한국 최저시급",
  "content": "2026년 최저시급은 시간당 10,470원이다. 월환산(209시간) 약 218만원...",
  "update_type": "dynamic",           // static | dynamic
  "update_cycle": "yearly",           // yearly | quarterly | monthly | weekly
  "last_updated": "2026-01-01",
  "persona_relevance": ["common"],    // common | [persona_ids]
  "priority": "high"                  // high | medium | low
}
```

### 5-2. 업데이트 전략
| 구분 | 업데이트 주기 | 소스 |
|------|-------------|------|
| K (시사/뉴스) | 주 1~2회 | RSS (연합뉴스, HN, Reddit) + 뉴스봇 수집분 |
| A2 (경제지표) | 월 1회 | 한국은행, 통계청 |
| F1 (대중문화) | 월 1~2회 | 엔터 뉴스, 차트 |
| D3 (AI동향) | 주 1회 | arXiv, HN, 테크 뉴스 |
| C2 (국제정세) | 월 1~2회 | 외신 요약 |
| 정적 지식 (B,E,J 등) | 분기 1회 검증 | 위키피디아, 교과서 |

### 5-3. 검색/주입 방식
1. **게시글 작성 시**: 페르소나 ID로 관련 전문 지식 청크 검색 + 공통 상식 중 토픽 관련 청크 검색
2. **댓글 작성 시**: 원글 키워드로 관련 팩트 청크 검색 → 페르소나 필터
3. **채팅 시**: 대화 키워드 → 실시간 RAG 검색 (상위 3~5 청크 주입)
4. **뉴스 번역 시**: 뉴스 카테고리 매칭으로 관련 배경지식 주입

### 5-4. 저장소 옵션
- **경량 (현재 아키텍처 호환)**: JSON 파일 + 키워드 매칭 (가장 빠른 구현)
- **중급**: SQLite + FTS5 전문검색 (설치 불필요, 빠름)
- **고급**: ChromaDB/Qdrant + 임베딩 벡터 검색 (정확도 최고)

### 5-5. 예상 규모
| 대분류 | 예상 청크 수 | 우선순위 |
|--------|------------|---------|

| B. 한국역사 | 100~150 | 높음 |
