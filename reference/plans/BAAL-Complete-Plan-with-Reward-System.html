3.2 🍯 꿀단지 리워드 광고 시스템 (신규)

💰 핵심 컨셉

광고 시청으로 실제 현금을 적립하는 리워드 시스템

평판(명예) ≠ 포인트(현금) 완전 분리

3.2.1 평판 vs 포인트 분리 전략

구분 평판 (Reputation) 포인트 (Point)
성격 명예 점수 가상 화폐
획득 방법 추천, 베스트 글, 변호인 승소 광고 시청 (꿀단지 전용)
용도 등급 표시, 권한 부여 현금 출금
거래 가능 ❌ 불가 (양도/판매 금지) ❌ 불가 (출금만 가능)
현금화 ❌ 불가 ✅ 가능 (5,000P = 5,000원)

✅ 왜 분리하는가?

  • 평판 보호: 돈으로 명예를 살 수 없음
  • 법적 안전: 포인트는 단순 광고 보상, 게임 아님
  • 어뷰징 방지: 평판 높아야 포인트 출금 가능 (평판 1000+ 필요)

3.2.2 꿀단지 4단계 페이지 구조

페이지 난이도 광고 형태 보상 개수 플랫폼 접근
🍯 1페이지 초간단 클릭 → 3초 대기 1원/건 20개 Desktop/Mobile 누구나
🍯 2페이지 쉬움 영상 10초 시청 3원/건 15개 Desktop/Mobile 1페이지 완료 후
🍯 3페이지 보통 설문 1분 10원/건 10개 Desktop/Mobile 2페이지 완료 후
🍯 4페이지 어려움 매장 방문 인증 (GPS) 50원/건 5개 Mobile만 3페이지 완료 후

매일 오전 10시 리셋 (일일 최대 획득: 20+45+100+250 = 415원)

🎮 게임화 요소

  • 진행바로 완료율 표시
  • 페이지 잠금 (순서대로 해금)
  • 누적 포인트 표시
  • 출금까지 남은 금액 표시

3.2.3 데스크톱 vs 모바일 차이

환경 이용 가능 페이지 일일 최대 획득
🖥️ Desktop 1~3페이지만 165원 (GPS 없음)
📱 Mobile 1~4페이지 전체 415원 (GPS 있음)

3.2.4 위치 기반 방문 인증 (4페이지, Mobile 전용)

📍 작동 원리

  1. 사용자가 꿀단지 4페이지 진입
  2. GPS 권한 요청 (브라우저 기본 기능)
  3. 근처 제휴 매장 목록 표시 (반경 1km)
  4. 매장 도착 → "방문 인증" 버튼
  5. 거리 검증 (50m 이내) → 50원 적립
  6. 위치 정보 즉시 삭제 (저장 안 함)
// 위치 기반 인증 로직
navigator.geolocation.getCurrentPosition((position) => {
  const userLat = position.coords.latitude;
  const userLng = position.coords.longitude;
  
  // 매장 위치
  const storeLat = 37.5665;
  const storeLng = 126.9780;
  
  // 거리 계산 (Haversine formula)
  const distance = calculateDistance(userLat, userLng, storeLat, storeLng);
  
  if (distance <= 50) { // 50m 이내
    // 포인트 적립
    awardPoints(userId, 50);
    // 위치 정보 삭제 (저장 안 함)
  } else {
    alert("매장에서 50m 이내에 있어야 합니다");
  }
});

⚠️ 주의사항

  • 위치 정보는 일회성 수집, 저장 금지
  • 사용자 동의 필수 (브라우저 권한 요청)
  • 실내 GPS 부정확 감안 (50m 허용 범위)
  • 하루 1회 제한 (같은 매장 중복 인증 불가)

5데이터베이스 설계

⚠️ 설계 원칙

  • 새 기능은 독립 테이블로 확장

5.1 핵심 공유 테이블

users (회원)

CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  oauth_provider VARCHAR(20) NOT NULL, -- 'kakao', 'naver', 'google'
  oauth_id VARCHAR(255) NOT NULL UNIQUE, -- 암호화된 OAuth ID
  nickname VARCHAR(50) NOT NULL, -- '익명404'
  
  -- 평판 (명예, 거래 불가)
  reputation INTEGER DEFAULT 0,
  trust_level VARCHAR(20) DEFAULT 'bronze', -- 'bronze', 'silver', 'gold', 'diamond'
  
  -- 포인트 (현금, 출금 가능) ← 신규
  points INTEGER DEFAULT 0,
  total_earned_points INTEGER DEFAULT 0, -- 누적 획득 (통계용)
  total_withdrawn INTEGER DEFAULT 0, -- 누적 출금 (통계용)
  
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW(),
  is_banned BOOLEAN DEFAULT FALSE,
  ban_reason TEXT,
  
  -- 통계
  posts_count INTEGER DEFAULT 0,
  comments_count INTEGER DEFAULT 0,
  upvotes_received INTEGER DEFAULT 0,
  downvotes_received INTEGER DEFAULT 0,
  
  CONSTRAINT oauth_unique UNIQUE(oauth_provider, oauth_id)
);

posts (게시글)

CREATE TABLE posts (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),

당신은 BAAL 커뮤니티 + 꿀단지 리워드 시스템을 개발하는 개발자입니다.

【절대 금지 사항】
1. AdSense 광고에 리워드 절대 금지
2. 꿀단지 페이지에 AdSense 배치 금지
3. 이메일/전화번호 수집 금지 (OAuth ID만)
4. 위치 정보 저장 금지 (일회성 인증만)
5. 평판 → 포인트 전환 금지 (완전 분리)

【핵심 원칙】
- 평판(명예): 거래 불가, 권한/등급용
- 포인트(현금): 출금 가능, 광고 시청으로만 획득
- 페이지 분리: 메인/게시판 = AdSense, /honey = 리워드 광고
- 부정 방지: IP 제한, VPN 차단, reCAPTCHA, 타이머 검증
- 법적 안전: 사업자등록, 통신판매업 신고, 원천징수

【기술 스택】
Frontend: Next.js 14 + TypeScript + TailwindCSS + Geolocation API
Backend: Supabase (PostgreSQL + Realtime + Auth + Edge Functions)
AI: Claude API (AI 판사)
Payment: 토스페이먼츠 (출금)
Ad Platforms: Tapjoy (클릭), AdGate (영상/설문), OfferToro (고보상)

【개발 단계】
Phase 1 (4주): 기본 커뮤니티
Phase 2 (3주): AI 판사 법정
Phase 3 (4주): 배심원 + 변호인
Phase 4 (3주): 실시간 관전
Phase 5 (4주): 꿀단지 리워드 (1~4페이지, GPS 인증)

【DB 설계 원칙】
- users 테이블에 reputation(평판), points(포인트) 분리
- 꿀단지: honey_ads, honey_activities, honey_withdrawals, honey_daily_limits
